# Task OS-005: Canonical Catalog Repository & Local Persistence

## Summary
Implement the first canonical repository boundary for **AstraZit Music OS**, establishing how validated canonical records (`WORK`, `RECORDING`, `RELEASE`) are locally stored, retrieved, updated, and protected with strict referential integrity, fail-closed corruption detection, and crash-resilient local persistence while keeping the physical storage backend replaceable.

## Technical Approach & Architecture Constraints
- **Canonical Model Alignment**: Top-level canonical entities are strictly `WORK`, `RECORDING`, and `RELEASE`.
- **Identity Handling**: Identifiers are allocated prior to persistence via `IdentifierAllocator`; repository never auto-allocates IDs on write.
- **Fail-Closed Persistence**: Any schema violation, missing reference, malformed JSON, duplicate key, or corrupted persisted file fails closed. Zero silent repair.
- **Single-Host Concurrency Boundary**: Advisory locking provides race-free coordination across threads and local OS processes on a single host. Does not claim distributed multi-host safety.
