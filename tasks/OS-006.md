# Task OS-006: Production Identifier Authority & Firestore Sequence Store

## Summary
Establish the first production-capable authoritative backend for **AstraZit Music OS** internal identifier allocation while preserving the exact OS-004 identifier contract and domain boundaries.

## Background & Context
Following ADR-012, ADR-014, and ADR-016:
- Production backend selected: **Google Cloud Firestore (Standard edition, Native mode)**.
- Replaces local JSON development persistence with a distributed, serializable ACID sequence store for production.
- Preserves exactly the three canonical namespaces (`WORK`, `RECORDING`, `RELEASE`) with numeric range `000001` through `999999`.
- Atomic sequence increment + append-only allocation ledger in a single transaction.
- Explicit authority state model (`INITIALIZING`, `ACTIVE`, `RECOVERY_REQUIRED`).
- Strict anti-rollback reconciliation gate: a restored database must never immediately resume allocation without verification that counters have not regressed behind ledger evidence.
- Zero cloud provisioning in this ticket: provisioning GCP resources is deferred to an explicit human-approved infrastructure ticket.

## Acceptance Criteria
- [x] AC-1: Preserves exact OS-004 namespaces (`WORK`, `RECORDING`, `RELEASE`) and formatting (`AST-WRK-XXXXXX`, `AST-REC-XXXXXX`, `AST-REL-XXXXXX`).
- [x] AC-2: Atomic sequence increment + append-only ledger creation in one transaction.

- [x] AC-7: Fake-client contention tested; unique monotonic IDs without gaps or duplicates under the fake's modeled transaction conflicts. Real Firestore/emulator concurrency was not run.
