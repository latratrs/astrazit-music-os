## 2. Architecture & Identity Isolation

### Non-Production Identity Guarantee
- User-visible public identifiers are explicitly distinct from production:
  - Works: DEMO-WRK-000001 .. DEMO-WRK-000003
  - Recordings: DEMO-REC-000001 .. DEMO-REC-000005
  - Releases: DEMO-REL-000001 .. DEMO-REL-000003
- Internal isolated schema-compliant fixture AST IDs (AST-WRK-000001, AST-REC-000001, etc.) exist **only** inside the isolated local sandbox repository directory.
- Neither FirestoreSequenceStore nor production IdentifierAllocator is ever called or initialized during sandbox lifecycle operations.
- The production SequenceStore state is untouched and zero production identifiers are consumed or reserved.
- Internal AST-shaped fixture IDs are sandbox implementation details only; normal CLI output accepts and displays DEMO IDs, and fixtures contain no operational external registration identifiers.

### Sandbox Root & Safety Marker
- Default directory: .local/demo-catalog/ (ignored via .gitignore).
- Safety marker: .demo-catalog.json contains:
  - mode: "DEMO"
  - production: false
  - schema_version: 1
  - created_at timestamp
  - warning notice
  - id_mapping dictionary
- Any destructive operation (
eset, init --force) strictly requires the presence and validity of .demo-catalog.json. If missing or invalid, operations fail closed to protect user and project files.
